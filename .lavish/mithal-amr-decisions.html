Decide  D1

وسع still comes out wrong — and the new function cannot fix it

You are right that the amr is سَعْ. The second branch of openMithalAmr() already handles that shape correctly: a dropped wāw leaves the word opening on a vowelled ʿayn, so no hamza is propped and nothing is rewritten — exactly how عِدْ and ضَعْ come out right.

But وسع never reaches that branch. It is bab: 'ia' in mithal.js:267, and the ia row keeps the wāw. So the stem handed to the function is already wrong:

Wasاِوْسَعْ
Nowاِيسَعْ
Correctسَعْ

The wāw→yāʾ conversion is doing its job. The stem underneath it is the problem.

No bāb in the table can express this verb

bābmāḍīmuḍāriʿverdict
ia وَسِعَ✓ يَوْسَعُ✗ wāw kept — what we ship today
ii وَسِعَ✓ يَسِعُ✗ drops, but wrong ʿayn vowel
aa وَسَعَ✗ يَسَعُ✓ right muḍāriʿ, wrong māḍī
wanted وَسِعَ✓ يَسَعُ✓ no bāb produces this pair

The ia row is hiding two different behaviours: the wāw stays (وَجِلَ يَوْجَلُ — the Qurʾānic لَا تَوْجَل the code comment cites) and the wāw drops (وَسِعَ يَسَعُ). The bāb's vowel pair does not decide which, so no amount of re-labelling fixes it — the fact has to live somewhere new.

Where should that fact live?

A · State the outcome on the root

A field on the Form I usage in the lexicon, e.g. faaDrops: true, read by the mithāl stem lookup before it consults the bāb.

Blunt and obvious. Says what happens, never why, so the next verb like this needs the same judgement call made again from scratch.

B · State the cause on the root Suggested

Record that the muḍāriʿ fatḥa is an opened kasra — the ḥarf ḥalq pulled it down — and let "wāw drops" follow from the rule the aa row already states.

Matches the reasoning already written in mithal-grammar.js, and answers D2 below with the same field rather than a second one.
